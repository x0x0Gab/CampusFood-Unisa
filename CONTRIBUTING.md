# Linee guida per la collaborazione

Questo repository contiene il progetto CampusFood-Unisa per il corso di Ingegneria del Software.

## Uso dei branch

Per mantenere il lavoro ordinato ogni modifica deve essere sviluppata su un branch dedicato, poi integrata in `main` tramite Pull Request.

Nomi branch:
- `docs/<nome>` per modifiche alla documentazione
- `feature/<nome>` per lo sviluppo del software
- `fix/<nome>` per correzioni

Esempi:
- `docs/rad`
- `feature/visualizzazione-menu`
- `fix/errori-formattazione`

## Pull Request

Quando una modifica è pronta:
1. Si apre una Pull Request verso `main`
2. Un altro membro del team deve effettuare la revisione
3. Dopo approvazione, si procede con il merge

Nella descrizione della PR è utile indicare sinteticamente cosa è stato aggiunto o modificato.

## Commit

I messaggi di commit devono essere brevi ma chiari riguardo alla modifica apportata.

Esempi:
- `docs: aggiunto primo elenco requisiti`
- `feat: implementata visualizzazione menu`
- `fix: corretta formattazione README`

## Issue

Per organizzare attività e assegnare compiti, utilizziamo le GitHub Issues.  
È consigliato collegare ogni Pull Request all’Issue corrispondente.

---

Lo scopo di queste regole è facilitare il lavoro di gruppo e mantenere il repository leggibile nel tempo.
